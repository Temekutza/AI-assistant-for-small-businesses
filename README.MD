## Введение

Этот проект — MVP Telegram-бота для Альфа-Хакатона. Бот является ИИ-помощником для владельцев малого бизнеса (например, кофейни), который отвечает на вопросы пользователя, используя локальную LLM (Ollama с моделью `qwen3:30b`) и RAG (Retrieval-Augmented Generation) на базе ChromaDB для поиска контекста из CSV-файлов. 
Проект построен на Python, использует Ollama для локальной генерации, LangChain для RAG, aiogram для Telegram-бота и python-dotenv для конфигурации. Бот загружает данные из папки `data/` при запуске (если БД пуста), чтобы обеспечить контекст для ответов. Нет приёма файлов от пользователя (по ТЗ хакатона).

**Цель:** Помогать с анализом продаж, маркетингом, юр. вопросами и финансами, используя RAG для точных ответов.

**Технологии:**
- **LLM:** Ollama (`qwen3:30b`)
- **RAG:** LangChain + ChromaDB + OllamaEmbeddings (`nomic-embed-text`)
- **Бот:** aiogram
- **Логи:** logging с файлом `bot.log`
- **Конфиг:** .env (токен, пути, модели)
- **Данные:** CSV из `data/` (например, `questions_clean.csv` — FAQ клиентов, `sample_sales.csv` — продажи)

## Что Сделано

- **Анализ ТЗ и Датасетов:** Проанализировали предоставленные CSV (`questions_clean.csv` — 6977 вопросов клиентов Альфа-Банка, `sample_submission.csv` — 6977 списков ID, вероятно для IR-задачи). Загружаем все файлы из `data/`, но фильтруем мусор (числа без текста). `websites.csv` пропускаем, если битый.
- **Архитектура:** Модульный код (main, bot, rag, llm, logging). Автозагрузка CSV при пустой БД.
- **RAG:** Загрузка в ChromaDB батчами (по 4000), поиск по similarity_search.
- **LLM:** Асинхронный вызов Ollama, лог ответов.
- **Бот:** Отвечает на любой текст, использует RAG для контекста, без приёма файлов.
- **Логи:** Полные логи (вопросы, ответы, ошибки) в `bot.log` и консоли.
- **Оптимизации:** Пропуск загрузки при заполненной БД, проверка БД в main.py, умный промпт для анализа дат.
- **Тестирование:** Бот отвечает на вопросы вроде "Сколько выручки в марте?" (из `sample_sales.csv`) или "Не приходят СМС?" (из `questions_clean.csv`).

 Время запуска: ~5–10 мин на загрузку (если БД пуста), мгновенно при повторных запусках.

## Как Работает

1. **Запуск:**
   - `main.py` — точка входа. Загружает .env, логи, инициализирует бота и RAG.
   - Проверяет ChromaDB: если пуста — загружает ВСЕ CSV из `data/`.
   - Запускает polling Telegram.

2. **Автозагрузка RAG (`bot.py`):**
   - Если БД пуста — ищет все *.csv в `data/`.
   - Загружает батчами (4000) в ChromaDB.
   - Фильтрует мусор (документы без букв — как в `sample_submission.csv`).
   - Если ошибка (как в `websites.csv`) — логирует, но бот не падает.

3. **RAG (`rag.py`):**
   - Инициализирует ChromaDB (локальная БД в `chroma_db/`).
   - `add_csv()`: Загружает CSV, разбивает на документы, добавляет в векторную БД.
   - `search()`: Поиск по similarity (k=5), возвращает контекст.

4. **LLM (`llm.py`):**
   - Асинхронный вызов Ollama.
   - Логирует промпт, время, полный ответ.

5. **Бот (`bot.py`):**
   - `/start`: Приветствие.
   - Любое сообщение: RAG-поиск → промпт с контекстом → LLM-ответ → отправка.
   - Промпт: "Ты — ИИ-помощник для малого бизнеса. Анализируй CSV...".
   - Без приёма файлов (handle_document удалён).

6. **Логи (`logging_config.py`):**
   - Файл `bot.log` + консоль.
   - Логирует всё: загрузку, вопросы, ответы LLM, ошибки.

## Текущие Проблемы

- **Проблемные CSV:** `sample_submission.csv` — числа, не текст (портит контекст). `websites.csv` — битый, вызывает ошибки. Решение: Удалить или фильтровать (уже в коде).
- **Долгая Загрузка:** 6977 документов — 5–10 мин (Ollama-эмбеддинги медленные). Решение: Уменьшить batch_size или использовать GPU.
- **Общие Ответы LLM:** Если контекст слабый (мусор в БД), ответы вроде "Уточните в банке". Решение: Улучшить промпт или очистить БД (`rm -rf chroma_db/`).
- **Нет Тестов:** Нет unit-тестов.
